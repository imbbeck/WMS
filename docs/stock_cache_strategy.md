# 재고 캐시 전략 설계서

## 1. 개요

WMS 시스템에서 재고 조회는 실시간 대시보드, 창고 현황 조회, 물류 작업 검증 등에서 지속적으로 호출되는 핵심 기능. Redis 기반의 캐시 전략을 통해 조회 성능을 최적화.

## 2. 캐시 키 구조

### 2.1 개별 재고 캐시
```
키 패턴: current_stock:{warehouseId}:{wareId}
값: 재고 수량 (Integer)
예시: current_stock:1:100 → 30
```

### 2.2 창고 총량 캐시
```
키 패턴: warehouse:{warehouseId}:currentSum  
값: 창고 총 재고량 (Integer)
예시: warehouse:1:currentSum → 150
```

### 2.3 창고 용량 캐시
```
키 패턴: warehouse:{warehouseId}:capacity  
값: 창고 수용 용량 (Integer)
예시:warehouse:1:capacity → 500
```

## 3. 캐시 무효화 전략

### 3.1 이벤트 기반 자동 갱신
- **재고 생성 시**: 개별 재고 캐시 생성, 창고 총량 증가
- **재고 수정 시**: 개별 재고 캐시 갱신, 창고 총량 증감 반영
- **재고 삭제 시**: 개별 재고 캐시 삭제, 창고 총량 감소

### 3.2 Write-Through 캐싱
- DB 업데이트와 동시에 캐시 갱신
- 트랜잭션 커밋 후 비동기 캐시 업데이트
- 데이터 일관성 보장

## 4. 조회 최적화 전략

### 4.1 창고 중심 조회 (캐시 활용)
- **개별 재고 조회**: 캐시 직접 조회
- **창고별 재고 목록**: Redis SCAN 패턴 매칭 (`current_stock:1:*`)
- **창고 집계 정보**: 총량 캐시 + SCAN 결과 조합
- **창고 사용률**: 캐시 기반 실시간 계산

### 4.2 물품 중심 조회 (DB 조회)
- **물품별 재고 목록**: 키 패턴 제약으로 DB 직접 조회
- **물품 집계 정보**: DB 집계 쿼리 활용
- **복잡한 검색 조건**: DB WHERE 절 활용

### 4.3 조회 타입별 최적화 방법

| 조회 타입 | 최적화 방법 | 사용 빈도 | 비고 |
|-----------|-------------|-----------|------|
| 개별 재고 조회 | 캐시 직접 조회 | 매우 높음 | 실시간 검증 |
| 창고별 재고 목록 | Redis SCAN | 높음 | 대시보드 |
| 창고 집계 정보 | 캐시 조합 조회 | 높음 | 현황 모니터링 |
| 물품별 재고 목록 | DB 직접 조회 | 낮음 | 패턴 제약 |
| 복잡한 검색 | DB 직접 조회 | 낮음 | 조건부 쿼리 |

## 5. Fallback 전략

### 5.1 캐시 실패 대응
- **1차**: 캐시에서 조회 시도
- **2차**: 캐시 실패 시 DB 조회
- **복구**: Redis 재연결 시 자동 캐시 Warming

### 5.2 부분 장애 처리
- **개별 캐시 miss**: 해당 항목만 DB 조회
- **전체 캐시 장애**: Circuit Breaker 패턴으로 DB 전환
- **데이터 불일치**: 수동 캐시 재구축 API 제공

## 6. 메모리 사용량 추정

```
예상 시스템 규모:
- 창고 수: 100개
- 물품 수: 10,000개  
- 재고 항목: 50,000개

캐시 메모리 사용량:
- 개별 재고 캐시: ~1.5MB
- 창고 총량 캐시: ~3.5KB
- 창고 용량 캐시: ~3KB
- 총 예상 사용량: ~1.5MB
```

## 7. 모니터링 및 운영

### 7.1 주요 메트릭
- **캐시 히트율**: 목표 95% 이상
- **평균 응답시간**: 캐시 조회 vs DB 조회
- **메모리 사용량**: Redis 인스턴스 모니터링
- **에러율**: 캐시 장애 및 Fallback 비율

### 7.2 운영 도구
- **캐시 상태 모니터링**: 실시간 히트율 대시보드
- **수동 캐시 관리**: 재구축 및 무효화 API
- **장애 대응**: 자동 Fallback 및 복구

## 8. 확장 계획

### 8.1 단기 개선
- 캐시 Warming 자동화
- 물품별 조회 최적화 (역인덱스 검토)
- 모니터링 대시보드 구축

### 8.2 장기 확장
- Redis Cluster 도입
- 지역별 캐시 분산
- 예측 기반 캐시 Prefetching

## 9. 결론

Redis 기반 재고 캐시 전략을 통해 다음을 달성:

- **성능 최적화**: 빈번한 창고 중심 조회의 캐시 활용
- **시스템 안정성**: DB 부하 분산 및 Fallback 보장  
- **확장성**: 메모리 효율적 캐시 구조
- **운영 효율성**: 자동화된 캐시 관리 및 모니터링

캐시를 효과적으로 활용할 수 있는 창고 중심 조회에 집중하고, 제약이 있는 물품 중심 조회는 DB를 활용하는 **하이브리드 접근법**으로 전체적인 성능과 안정성을 확보.
