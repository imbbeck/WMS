# 물류 관리 시스템 (WMS - Warehouse Management System)

> **Spring Boot + JPA 기반의 물류 창고 관리 시스템**

## 📋 프로젝트 개요

입고, 출고, 창고간 이동을 통한 물류 이동 관리 시스템으로, 실시간 작업 진행 모니터링과 재고 관리 기능을 제공합니다.

### 🎯 주요 기능

- **실시간 작업 대시보드**: 당일 물류 작업 진행 상황 모니터링
- **작업 계획 수립**: 전날 결과 분석을 통한 효율적인 작업 계획
- **재고 관리**: 창고별 재고 현황 및 용량 관리
  - 재고 create, put, delete는 admin만 가능, 재고 수량 증가/감소는 작업 시작/완료시 자동으로 처리되고 수동으로는 변경 불가 
- **장소 관리**: 장소 등록 및 이동 소요시간 관리
- **작업자 관리**: 작업 할당 및 성과 추적
- ~~**히스토리 분석**: 과거 작업 데이터 기반 성과 분석~~ (엔티티 + 히스토리데이터 생성하는 배치 프로세스까지만 구현)

## 📊 비즈니스 로직

### 당일 물류 이동 계획 수립시 물류작업을 생성/수정/삭제할때마다, 기 존재하는 작업들과 상호작용하여 예상되는 출발지의 재고유무/도착지의 남은 수용량을 체크해 작업의 유효성을 검증.

### 물류 이동의 결과로만 재고 변화가 발생
- 이벤트 발행/구독으로 비동기 처리

### 물류 이동 작업 관리

#### 1. 당일 작업 관리
- 모든 물류 작업은 **하루 단위**로 관리
- 자정 배치 프로세스로 히스토리 이동 및 테이블 정리
- 실시간 대시보드는 당일 데이터만 조회하여 **빠른 성능** 보장

#### 2. 작업 상태 흐름
```
PENDING → INITIATED → COMPLETED
    ↓         ↓           ↓
CANCELLED  FAILED    COMPLETE_DELAYED
    ↓         ↓           ↓
   자정 배치 시 모든 상태 → HISTORY
```

#### 3. 미완료 작업 처리
- 당일 완료되지 못한 작업: `EXPIRED` 상태로 히스토리 보관
- 계획자가 다음날 계획 수립 시 참고 자료로 활용

## 🎯 설계 원칙

### DDD (Domain Driven Design)
- 각 도메인별 독립적인 Aggregate 설계
- 의도적인 매핑 제거로 성능 최적화
- 비즈니스 로직 중심의 엔티티 설계
- Aggregate 간의 관계 최소화
  - Aggregate 외부 상태변화(물류 작업 완료 처리 후 재고변화 등)는 event를 통한 비동기 처리
    - 향후 mq를 통한 이벤트 처리로 확장 가능성 고려한 구조 설계
- Domain Exception을 통한 비즈니스 규칙 검증
  - Factory Method + Composite + Template Method Pattern 적용으로 재사용성에 중점을 둔 Exception 구조 

### Clean Architecture
- **Use Case 중심**: 각 도메인별 Use Case로 비즈니스 로직 분리
- **계층화된 아키텍처**: Presentation, Application, Domain, Infrastructure 계층으로 분리하고 각 계층간 책임을 명확하게

### 성능 최적화
- **캐싱**: 재고 등을 캐싱하여 조회 성능 향상
- **당일 작업 테이블**: 항상 작은 크기 유지
- **선별적 FK 적용**: 필요한 곳에만 참조 무결성 보장
- **스냅샷 저장**: 히스토리 조회 시 JOIN 최소화

### 운영 효율성
- **자정 배치**: 자동화된 데이터 정리
- **계획 지원**: 전날 결과 기반 다음날 계획 수립
- **실시간 모니터링**: 당일 작업 진행 상황 추적
